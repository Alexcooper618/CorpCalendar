# CorpCalendar

Подробное руководство по запуску и краткое описание системы годового календаря для планирования корпоративных опросов.

## Как запустить через Docker (Windows PowerShell)

Ниже приведена последовательность действий от открытия терминала до проверки работы приложения.

1. **Установите Docker Desktop** (если он ещё не установлен) и убедитесь, что команда `docker` доступна в PowerShell.
2. **Откройте PowerShell** и перейдите в каталог проекта. Пример для локальной копии в папке `Documents`:
   ```powershell
   cd C:\Users\<ваш_пользователь>\Documents\CorpCalendar
   ```
3. **Запустите сборку и старт контейнеров** (команда выполняется в корне репозитория, где лежит `Docker-compose.yml`):
   ```powershell
   docker compose -f Docker-compose.yml up --build
   ```
   - Docker соберёт два контейнера: `backend` (NestJS + SQLite) и `frontend` (Next.js).
   - В каталоге `backend` автоматически создастся постоянный том `backend_data` для SQLite базы `/app/data/calendar.db`.
4. **Дождитесь старта сервисов**. В логах появятся сообщения о запуске backend на порту 4000 и frontend на 3000.
5. **Откройте приложение в браузере**:
   - Web-интерфейс: <http://localhost:3000>
   - REST API (для проверки): <http://localhost:4000/api/events>
6. **Остановка контейнеров** — в том же PowerShell нажмите `Ctrl+C`, затем по желанию очистите контейнеры и сеть:
   ```powershell
   docker compose -f Docker-compose.yml down
   ```

> Примечание: если вы запускаете из другой папки, замените путь в шаге 2 на расположение вашего клона проекта. Команды `docker compose ...` должны выполняться из корня репозитория.

## Как работает система

### Общая схема
- **Frontend (Next.js)** — приложение в каталоге `frontend` показывает годовой календарь, позволяет добавлять/редактировать/удалять события, отмечает выходные и государственные праздники, открывает модальные окна для деталей дня и формы события. API-адрес берётся из `NEXT_PUBLIC_API_URL` (в Docker задан `http://localhost:4000`).
- **Backend (NestJS)** — сервис в каталоге `backend` предоставляет REST API под префиксом `/api` и работает с SQLite через `better-sqlite3`. Файл базы хранится по пути `/app/data/calendar.db` (настраивается переменной `SQLITE_PATH`).
- **Docker Compose** — описан в `Docker-compose.yml` и поднимает оба сервиса с пробросом портов `3000` (frontend) и `4000` (backend).

### API и хранение данных
- `GET /api/events` — список всех событий, отсортированный по датам.
- `POST /api/events` — создание события. Обязательны `title`, `startDate`, `endDate`; даты должны быть в ISO-формате и дата окончания не раньше начала.
- `PATCH /api/events/:id` — обновление выбранного события с валидацией дат и обязательности названия.
- `DELETE /api/events/:id` — удаление события.
- Событие содержит: название, период (`startDate`/`endDate`), подразделение (`dept`), ответственного (`owner`), цветовую метку (`color`), комментарий (`comment`).

### Взаимодействие интерфейса с API
- При загрузке календаря фронтенд делает запрос `GET /api/events` и раскрашивает дни для каждого события.
- Клик по пустой ячейке дня открывает форму создания события с предустановленным диапазоном дат.
- Клик по дню с событиями показывает модальное окно с перечнем событий, кнопками редактирования и удаления; после успешных операций интерфейс запрашивает список событий заново.
- Праздничные даты подсвечиваются жёлтым, выходные — серым, текущий день выделяется цветом.

## Полезные команды для разработки без Docker (опционально)
Если хотите запускать части приложения напрямую, а не через Docker:
- Backend: `cd backend` → `npm install` → `npm run start:dev` (по умолчанию порт 4000, база в `backend/data` или путь из `SQLITE_PATH`).
- Frontend: `cd frontend` → `npm install` → `npm run dev` (по умолчанию порт 3000; для связи с API установите переменную `NEXT_PUBLIC_API_URL=http://localhost:4000`).
